# Известные проблемы

Список составлен при анализе кода 14.11.2026. Пункты ниже, кроме раздела исправленных, найдены чтением исходников. Нумерация пунктов сохранена с первой версии списка, пункты 2–5 перенесены в раздел исправленных.

## Исправлено 14.11.2026

Проверено запуском сервера и запросами через `curl`, кроме пунктов с пометкой.

- **Виртуальное окружение** пересоздано под Python 3.14.
- **Версии в `requirements.txt`.** `asyncpg` поднят с 0.29.0 до 0.32.0 (у старой версии нет сборки под 3.14), `sqlalchemy` — с 2.0.32 до 2.0.57 (старая падала при импорте моделей). Остальные версии не менялись.
- **Пакеты в `requirements.txt`.** Добавлены `python-jose`, `python-dotenv`, `python-multipart`.
- **`AuthMiddleware` отвечал 500 вместо 401.** Теперь без токена и с неверным токеном приходит 401 с CORS-заголовками.
- **`AuthMiddleware` блокировал CORS-preflight.** Он добавляется до `CORSMiddleware` и пропускает метод `OPTIONS`; preflight к `/products/` возвращает 200.
- **Роутер `locations`** подключён в `app/main.py`; создание места хранения проверено на живой базе.
- **База данных.** PostgreSQL на машине не установлен, поэтому добавлен запуск через Docker (`docker-compose.yml`). Стек поднимается, миграции применяются при старте.
- **Роли и пользователи.** Открытая регистрация `/auth/register` удалена: раньше любой мог создать себе администратора. Пользователей создаёт только администратор через `/users`; добавлено отключение учётных записей (`users.is_active`). Проверено 27 проверками API и вручную в браузере.
- **Зависимость `get_current_active_user`** обращалась к несуществующему полю `is_active`; заменена на `get_current_user`, который проверяет это поле.
- **Резка.** Прежняя `cut_product` (складывала куски в строку с количеством, не проверяла длину) удалена. Вместо неё поштучный учёт и `POST /cuts/`; проверено сценарием из 43 проверок на живой базе.

Создание товара, типа, материала, места хранения и приход заготовок проверены вручную в браузере. Удаление товаров, типов и материалов через интерфейс не проверялось.

## Ошибки в работе

### 7. Товары без имени ломают список

`products.name` в БД допускает `NULL`, а схема `ProductRead` требует строку. Если в таблице окажется запись без имени (например, созданная до миграции `509bd94a01e2` или напрямую в БД), `GET /products/` начнёт отдавать 500 на валидации ответа.

### 8. Откат миграции `79c14ac440ea` не сработает

Внешний ключ создан и удаляется с именем `None`. Подробности в [DATABASE.md](DATABASE.md).

## Безопасность

### 9. Права работника не ограничены

Создавать пользователей может только администратор, но все остальные действия доступны любому вошедшему: работник может удалять товары, типы и материалы, закрывать заказы. Если это нежелательно, на соответствующие эндпоинты нужно поставить `require_admin`.

### 10. Прежний пароль администратора остался в истории git

Скрипт `scripts/create_admin.py` теперь берёт пароль из `ADMIN_PASSWORD` в `.env`, но старое значение, записанное в коде, осталось в прошлых коммитах. Если оно ещё используется, его нужно сменить.

### 11. Мелочи

- `/health` требует токен, поэтому внешний мониторинг без авторизации его не опросит.
- `create_async_engine(..., echo=True)` пишет в лог каждый SQL-запрос. Для разработки удобно, для продакшена нет.
- Пароли хешируются через `sha256_crypt`, хотя в зависимостях стоит `passlib[bcrypt]`.
- JWT хранится в `localStorage` и уязвим при XSS.
- В `.env` есть переменные `PG_UNSERNAME` (с опечаткой) и `PG_PASSWORD`, которые код не читает.

## Недоделано

- **Фронтенд для заказов и резки.** Есть страницы прихода заготовок, товаров и справочников; страниц для заказов, резки, резерва и истории заготовки нет, есть только API.
- **Места хранения нельзя удалить или переименовать**: в API есть только список и создание.
- **Расчёт потребности заказа.** Система не знает, сколько каких кусков нужно на ворота заданного размера: что резать, решает человек.
- **Оптимизация раскроя.** Система не подсказывает, из какой заготовки выгоднее резать.
- **Автотесты.** Сценарий проверки резки был разовым и в репозиторий не добавлен.
- **Продажа штучного товара** не выведена в API (`sell_product` в `app/repo/inventory.py`).
- **Редактирование товара**: есть только схема `ProductUpdate`.
- **`required_attributes`** у типа хранится, но при создании товара не проверяется.
- **`Location.capacity`** хранится, но не проверяется.
- **Тестов нет** ни на бэкенде, ни на фронтенде.

## Порядок в репозитории

- В корне лежат `package.json`, `package-lock.json` и `node_modules/` с единственной зависимостью `react-router-dom`. Она уже есть в `frontend/package.json`, так что корневые файлы, судя по всему, появились от случайного `npm install` не в том каталоге. Корневой `.gitignore` не исключает `node_modules/`.
- В `app/models/Alchemy_models.py` импорты повторяются в середине файла.
- JWT обслуживают две библиотеки: PyJWT для выпуска и python-jose для проверки. Достаточно одной.
- Каталог `app/service/` пуст.
- `frontend/README.md` — шаблон Vite без сведений о проекте.
- В рабочей копии много незакоммиченных изменений: роутер и миграция для мест хранения, middleware, переписанный `App.jsx`.
