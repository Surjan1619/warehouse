# API

Базовый адрес: `http://localhost:8000`. Интерактивная документация: `/docs`.

Все эндпоинты, кроме отмеченных как публичные, требуют заголовок с токеном действующего (не отключённого) пользователя:

```
Authorization: Bearer <access_token>
```

## Служебные

| Метод | Путь | Доступ | Ответ |
|---|---|---|---|
| GET | `/` | Публичный | `{"message": "Welcome to WMS API"}` |
| GET | `/health` | Нужен токен | `{"status": "ok"}`, выполняет `SELECT 1` в БД |

## Авторизация — `/auth`

Открытой регистрации нет: учётные записи создаёт администратор через `/users`.

### POST `/auth/login` (публичный)

Тело в формате `application/x-www-form-urlencoded`: `username`, `password`.

```json
{
  "access_token": "...",
  "token_type": "bearer",
  "user": {"id": 1, "username": "admin", "role": "admin", "is_active": true}
}
```

При неверном имени, неверном пароле или отключённой учётной записи ответ одинаковый: 400 `Incorrect username or password`.

### GET `/auth/me`

Возвращает пользователя, которому принадлежит токен: `{"id", "username", "role", "is_active"}`.

## Пользователи — `/users` (только администратор)

Все эндпоинты требуют роль `admin`; остальным возвращается 403 `Admin access required`.

| Метод | Путь | Описание |
|---|---|---|
| GET | `/users/` | Список пользователей |
| POST | `/users/` | Создать пользователя (201); 409, если имя занято |
| PATCH | `/users/{id}` | Сменить пароль или роль, отключить или включить |

Создание:

| Поле | Тип | Ограничения |
|---|---|---|
| `username` | строка | 3–50 символов, уникально |
| `password` | строка | 6–128 символов |
| `role` | строка | `worker` (по умолчанию) или `admin` |

Изменение: любые из полей `password`, `role`, `is_active`. Администратор не может отключить собственную учётную запись или сменить себе роль (400).

Пользователи не удаляются, а отключаются (`is_active: false`): на них ссылается история резок. Отключённый пользователь не может войти, а его действующий токен перестаёт приниматься сразу.

Пароль в ответах не возвращается.

## Журнал действий — `/activity` (только администратор)

### GET `/activity/`

Записи журнала от новых к старым. Остальным ролям возвращается 403.

| Параметр | Тип | Примечание |
|---|---|---|
| `user_id` | целое | кто сделал |
| `action` | строка | `receive`, `cut`, `use`, `scrap` |
| `material_id` | целое | |
| `stock_item_id` | целое | записи об одной заготовке |
| `date_from` | дата-время | включительно; передавать со смещением, например `2026-11-10T00:00:00+04:00` |
| `date_to` | дата-время | не включая |
| `limit` | целое | 1–200, по умолчанию 50 |
| `offset` | целое | по умолчанию 0 |

```json
{
  "total": 37,
  "items": [
    {
      "id": 12,
      "created_at": "2026-11-15T07:47:50.890093+00:00",
      "action": "cut",
      "user": {"id": 1, "username": "admin"},
      "material": {"id": 1, "name": "rollet"},
      "stock_item": {"id": 33, "code": "T-000033", "length_mm": 1000},
      "cut_operation_id": 9,
      "quantity": 1,
      "length_mm": 1000,
      "details": {"pieces_mm": [100], "remainder_mm": 900}
    }
  ]
}
```

- `total` — сколько записей подходит под фильтры без учёта `limit` и `offset`.
- `created_at` всегда в UTC и с явным смещением: браузер сам переводит его в местное время.
- Что означают `quantity`, `length_mm` и `details` для каждого действия, описано в [DATABASE.md](DATABASE.md).

## Товары — `/products`

### GET `/products/`

Список всех товаров с вложенными типом и местом хранения.

```json
[
  {
    "id": 1,
    "name": "Лист стальной",
    "length": 2000.0,
    "width": 1000.0,
    "thickness": 2.0,
    "shape": "sheet",
    "weight": 31.4,
    "quantity": 10,
    "product_type_id": 1,
    "location_id": null,
    "product_type": {"id": 1, "name": "Сталь", "required_attributes": {}},
    "location": null
  }
]
```

### POST `/products/`

| Поле | Тип | Обязательное | Ограничения |
|---|---|---|---|
| `name` | строка | да | не пустая |
| `quantity` | целое | нет | ≥ 0, по умолчанию 0 |
| `length`, `width`, `thickness`, `weight` | число | нет | ≥ 0 |
| `shape` | строка | нет | до 50 символов |
| `product_type_id` | целое | нет | id существующего типа |
| `location_id` | целое | нет | id существующего места |

Ответ: созданный товар в формате, как в списке.

### DELETE `/products/{product_id}`

Ответ: `{"message": "Product deleted"}`. Если товара нет — 404.

## Типы товаров — `/products/types`

### GET `/products/types`

Ответ: `[{"id": 1, "name": "Сталь", "required_attributes": {}}]`.

### POST `/products/types`

| Поле | Тип | Обязательное |
|---|---|---|
| `name` | строка, 1–100 символов | да |
| `required_attributes` | объект | нет |

Если тип с таким именем уже есть, возвращается существующий, без ошибки и без обновления `required_attributes`.

### DELETE `/products/types/{type_id}`

Ответ: `{"message": "Type deleted"}`. Если тип не найден или к нему привязаны товары — 400 с одним и тем же сообщением для обоих случаев.

## Поштучный учёт и резка

Длины везде в миллиметрах, целыми числами. Ошибки бизнес-правил возвращаются как `{"detail": "..."}` с кодом 400, «не найдено» — 404, конфликт уникальности — 409.

### Материалы — `/materials`

Справочник того, что режется: профили, направляющие, валы.

| Метод | Путь | Описание |
|---|---|---|
| GET | `/materials/` | Список |
| POST | `/materials/` | Создать (201) |
| PATCH | `/materials/{id}` | Изменить переданные поля |
| DELETE | `/materials/{id}` | Удалить; 400, если есть заготовки этого материала |

| Поле | Тип | Примечание |
|---|---|---|
| `name` | строка | обязательное, до 100 символов |
| `kind` | строка | вид: профиль, направляющая, вал… |
| `sku` | строка | артикул, уникальный |
| `color` | строка | |
| `kerf_mm` | целое | ширина реза, по умолчанию 0 (потери на рез не учитываются) |
| `min_usable_length_mm` | целое | остаток короче этого уходит в отходы, по умолчанию 300 |

### Заказы — `/orders`

| Метод | Путь | Описание |
|---|---|---|
| GET | `/orders/?status=` | Список, новые сверху |
| POST | `/orders/` | Создать (201) |
| GET | `/orders/{id}` | Заказ с его заготовками (`items`) и их суммарной длиной (`total_length_mm`) |
| PATCH | `/orders/{id}` | Изменить переданные поля, включая `status` |

Поля: `customer_name` (обязательное), `number`, `customer_phone`, `address`, `gate_type`, `width_mm`, `height_mm`, `note`. Если `number` не передан, он создаётся автоматически в виде `ORD-00001`.

Статусы: `new`, `in_progress`, `done`, `cancelled`. При переводе в `done` зарезервированные заготовки заказа становятся `used`. При переводе в `cancelled` они возвращаются на склад и отвязываются от заказа.

### Заготовки — `/stock-items`

Каждая запись — одна физическая труба или кусок.

| Метод | Путь | Описание |
|---|---|---|
| GET | `/stock-items/` | Список с фильтрами `status`, `material_id`, `order_id`, `location_id`, `min_length_mm`, `number`; без ограничения длины |
| GET | `/stock-items/summary?status=&location_id=` | Сводка по материалам: `material`, `count`, `total_length_mm`, `min_length_mm`, `max_length_mm`. Только материалы, у которых есть такие заготовки, по названию |
| GET | `/stock-items/page?status=&material_id=&location_id=&limit=50&offset=0` | Страница списка: `{"items": [...], "total": 137}`, сначала самые длинные, при равной длине — старые. `limit` от 1 до 200 |
| POST | `/stock-items/` | Приход: создать `count` заготовок одной длины (201) |
| GET | `/stock-items/{id}` | Одна заготовка |
| GET | `/stock-items/{id}/history` | Происхождение: `ancestors` (от родителя до исходной трубы) и `children` (что из неё вырезано) |
| PATCH | `/stock-items/{id}` | Сменить `location_id`, `note` или исправить `length_mm` |
| POST | `/stock-items/{id}/assign` | Зарезервировать за заказом: `{"order_id": 1}` |
| POST | `/stock-items/{id}/release` | Снять резерв |
| POST | `/stock-items/{id}/use` | Отметить использованной в заказе |
| POST | `/stock-items/{id}/scrap` | Списать в отходы |

Поиск по номеру: `GET /stock-items/?number=T-000123`. Номер можно писать как на трубе или короче: `T-000123`, `t123`, `123`, `№ 123`, с русской «Т». Совпадение точное: `1` не найдёт `T-000010`. Ответ — список из одной заготовки или пустой; статус не важен, пока не задан фильтр `status`. Нераспознанный номер — 422.

Приход: `{"material_id": 1, "length_mm": 6000, "count": 3, "location_id": 2}`.

Статусы и переходы:

| Статус | Значение | Откуда |
|---|---|---|
| `in_stock` | свободна на складе | приход, резка, `release`, отмена заказа |
| `reserved` | закреплена за заказом | `assign`, резка с `order_id` |
| `used` | израсходована | резка с `used`, `use`, закрытие заказа |
| `cut` | разрезана, больше не существует целиком | резка |
| `scrap` | отходы | `scrap`, короткий остаток после резки |

Ответ содержит `code` — номер вида `T-000123`, который пишется на самой трубе, и `created_by` — `{"id", "username"}` того, кто принял заготовку или сделал резку, из которой она получилась (`null` у старых записей).

### Резка — `/cuts`

| Метод | Путь | Описание |
|---|---|---|
| POST | `/cuts/suggest` | Подобрать, из чего резать; ничего не меняет |
| POST | `/cuts/plan` | Разложить куски по нескольким заготовкам; ничего не меняет |
| POST | `/cuts/batch` | Разрезать несколько заготовок одной операцией (201) |
| POST | `/cuts/` | Разрезать заготовку (201) |
| POST | `/cuts/{id}/cancel` | Отменить резку |
| GET | `/cuts/?source_item_id=&limit=` | Последние операции, включая отменённые (`cancelled_at` не пустой) |
| GET | `/cuts/{id}` | Одна операция с результатами |

Запрос:

```json
{
  "source_item_id": 1,
  "pieces": [
    {"length_mm": 2500, "order_id": 1},
    {"length_mm": 2500, "used": true}
  ],
  "kerf_mm": 3,
  "scrap_remainder": false,
  "note": "необязательно"
}
```

- Кусок с `"used": true` сразу получает статус `used` (израсходован). Иначе кусок с `order_id` создаётся со статусом `reserved`, а без него — `in_stock`. `used` и `order_id` можно указать вместе: кусок израсходован в этом заказе.
- `kerf_mm` можно не передавать, тогда берётся значение из материала.
- `scrap_remainder: true` списывает остаток в отходы, даже если он длиннее минимального.
- У куска можно указать `location_id`; иначе он остаётся там, где лежала исходная труба.

Ответ содержит исходную заготовку (`source_item`, уже со статусом `cut`), потери на рез (`kerf_loss_mm`), идентификатор сотрудника (`user_id`) и `results` — запрошенные куски и остаток, если он есть. Для примера выше из трубы 6000 мм при ширине реза 3 мм получится два куска по 2500 (первый в резерве за заказом 1, второй израсходован), потери 6 мм и остаток 994 мм. При ширине реза 0 остаток будет ровно 1000 мм.

#### Подбор заготовки — POST `/cuts/suggest`

Запрос: материал и длины нужных кусков.

```json
{"material_id": 1, "pieces": [3000]}
```

Ответ: свободные заготовки этого материала, в которые помещаются все куски, от самой экономной к наименее экономной.

```json
{
  "required_mm": 3000,
  "longest_available_mm": 7000,
  "candidates": [
    {"item": {"id": 34, "code": "T-000034", "length_mm": 3000}, "item_ids": [34], "count": 1,
     "remainder_mm": 0, "kerf_loss_mm": 0, "remainder_fate": "none"},
    {"item": {"id": 31, "code": "T-000031", "length_mm": 7000}, "item_ids": [31, 32, 33], "count": 3,
     "remainder_mm": 4000, "kerf_loss_mm": 0, "remainder_fate": "stock"}
  ]
}
```

- **Порядок:** чем меньше остаток, тем выше. Точное совпадение идёт первым, короткий обрезок — раньше целой трубы. При равном остатке выше более старая заготовка.
- **Группы:** заготовки одной длины в одном месте взаимозаменяемы и возвращаются одной строкой; `item` — самая старая из них, `item_ids` — все, `count` — их число.
- **`remainder_fate`:** `none` — заготовка уйдёт целиком, `stock` — остаток вернётся на склад, `scrap` — остаток короче минимального и уйдёт в отходы.
- **Пустой список** означает, что ни одна заготовка не вмещает все куски разом; `longest_available_mm` показывает самую длинную свободную.

`/cuts/suggest` ищет одну заготовку под весь список кусков. Если такой нет, используется раскладка.

#### Раскладка по нескольким заготовкам — POST `/cuts/plan`

```json
{"material_id": 1, "pieces": [{"length_mm": 3000, "used": true}, {"length_mm": 3000, "used": true}, {"length_mm": 3000}]}
```

Куски передаются в том же виде, что и при резке (`length_mm`, `used`, `order_id`, `location_id`, `note`), и возвращаются распределёнными по заготовкам:

```json
{
  "cuts": [
    {"item": {"id": 12, "code": "T-000012", "length_mm": 7000},
     "pieces": [{"length_mm": 3000, "used": true}, {"length_mm": 3000, "used": true}],
     "remainder_mm": 1000, "kerf_loss_mm": 0, "remainder_fate": "stock"},
    {"item": {"id": 13, "code": "T-000013", "length_mm": 7000},
     "pieces": [{"length_mm": 3000, "used": false}],
     "remainder_mm": 4000, "kerf_loss_mm": 0, "remainder_fate": "stock"}
  ],
  "unplaced": [],
  "longest_available_mm": 7000
}
```

- `cuts` идут от самой заполненной заготовки к наименее заполненной.
- `unplaced` — куски, которым не нашлось места: они длиннее любой свободной заготовки либо заготовки закончились.
- Правила раскладки описаны в [ARCHITECTURE.md](ARCHITECTURE.md). Это эвристика: результат хороший, но не всегда наилучший из возможных.

#### Резка нескольких заготовок — POST `/cuts/batch`

```json
{"cuts": [{"source_item_id": 12, "pieces": [{"length_mm": 3000, "used": true}]}, {"source_item_id": 13, "pieces": [{"length_mm": 3000}]}]}
```

Ответ — список операций в том же виде, что у `POST /cuts/`. Сохраняется либо всё, либо ничего: если хотя бы одна резка невозможна (заготовку уже разрезали, куски не помещаются, заготовка указана дважды), не выполняется ни одна. До 50 резок за раз.

Резать можно только заготовку в статусе `in_stock` или `reserved`. Если куски не помещаются, заказ закрыт или не существует, ничего не записывается.

#### Отмена резки — POST `/cuts/{id}/cancel`

Доступна всем ролям. Отменить можно любую резку, не только последнюю. Исходная заготовка получает статус, который был у неё до резки: `reserved`, если она была зарезервирована за заказом и заказ ещё открыт, иначе `in_stock`. Все куски этой резки, включая остаток и отходы, получают статус `cancelled` и отвязываются от заказа. Ничего не удаляется; у операции заполняются `cancelled_at` и `cancelled_by_id`.

Отказ с 409: резка уже отменена, или один из её кусков разрезан дальше. Во втором случае сначала нужно отменить ту, более позднюю резку; номера кусков есть в тексте ошибки. Резка из `POST /cuts/batch` состоит из нескольких операций, каждая отменяется отдельно. В журнал отмена пока не пишется (решение владельца от 16.11.2026).

#### Правка длины — PATCH `/stock-items/{id}`

`{"length_mm": 6950}` исправляет длину, введённую неверно при приходе. Доступно всем ролям. Разрешено только для принятой на склад заготовки (`parent_id` пустой) в статусе `in_stock` или `reserved`, иначе 400. Длина куска, полученного резкой, следует из резки: чтобы её исправить, нужно отменить резку, исправить исходную заготовку и разрезать заново. У штучных товаров (`products`) эндпоинта правки нет. В журнал правка пока не пишется.

## Не реализовано в API

- Редактирование товара: схема `ProductUpdate` есть, эндпоинта нет.
- Продажа штучного товара: функция `sell_product` в `app/repo/inventory.py` и схемы `SaleProductRequest`, `InventoryResponse` есть, эндпоинта нет.
- История движений (`movements`): только запись, чтения нет.
